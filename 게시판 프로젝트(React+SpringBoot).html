💡 domain/Post.java
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
@EntityListeners(AuditingEntityListener.class)
@Entity
public class Post {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)   // PK 자동 증가
    private Long id;

    @Column(nullable = false)
    private String title;       // 글 제목

    @Column(nullable = false, columnDefinition = "TEXT")  // 긴 본문
    private String content;     // 글 내용

    @Column(length = 20, nullable = false)
    private String writer;      // 글쓴이

    @CreatedDate
    private LocalDateTime createdAt;   // 작성일

    @LastModifiedDate
    private LocalDateTime updatedAt;   // 수정일

    @Builder   // 빌더 패턴으로 객체 생성
    public Post(String title, String content, String writer) {
        this.title = title;
        this.content = content;
        this.writer = writer;
    }

    // 요청 받은 값으로 수정 (트랜잭션 안에서 호출 → 자동 UPDATE)
    public void update(String title, String content) {
        this.title = title;
        this.content = content;
    }
}

@Getter
public class PostResponse {
    private final Long id;
    private final String title;
    private final String content;
    private final String writer;
    private final LocalDateTime createdAt;
    private final LocalDateTime updatedAt;

    public PostResponse(Post post) {   // 엔티티 → 응답 DTO
        this.id = post.getId();
        this.title = post.getTitle();
        this.content = post.getContent();
        this.writer = post.getWriter();
        this.createdAt = post.getCreatedAt();
        this.updatedAt = post.getUpdatedAt();

💡 service/PostService.java
@RequiredArgsConstructor
@Service
public class PostService {
    private final PostRepository postRepository;

    public Post save(AddPostRequest request){
        return postRepository.save(request.toEntity());
    }

    public List<Post> findAll(){
        return postRepository.findAll(Sort.by(Sort.Direction.DESC, "id"));
    }

    public Post findById(Long id){
        return postRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("not found: " + id));
    }

    public void delete(Long id){
        postRepository.deleteById(id);
    }

    @Transactional
    public Post update(Long id, UpdatePostRequest request){
        Post post = postRepository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("not found: " + id));

        post.update(request.getTitle(), request.getContent());
        return post;
    }
}
💡 controller/PostApiController.java
@RequiredArgsConstructor
@RequestMapping("/api/posts")
@RestController
public class PostApiController {
    private final PostService postService;

    @PostMapping
    public ResponseEntity<PostResponse> addPost(@RequestBody AddPostRequest request){
        Post saved = postService.save(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(new PostResponse(saved));
    }

    @GetMapping
    public ResponseEntity<List<PostResponse>> findAllPosts(){
        List<PostResponse> posts = postService.findAll()
                .stream()
                .map(PostResponse::new)
                .toList();
        return ResponseEntity.ok().body(posts);
    }

    @GetMapping("/{id}")
    public ResponseEntity<PostResponse> findPost(@PathVariable Long id){
        Post post = postService.findById(id);
        return ResponseEntity.ok().body(new PostResponse(post));
    }

    //body를 넣지 않았기 때문에 응답 본문은 비어 있습니다.
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deletePost(@PathVariable Long id){
        postService.delete(id);
        return ResponseEntity.ok().build();
    }

    @PutMapping("/{id}")
    public ResponseEntity<PostResponse> updatePost(@PathVariable Long id,
           @RequestBody UpdatePostRequest request){
        Post post = postService.update(id, request);
        return ResponseEntity.ok().body(new PostResponse(post));
    }
}

2-2. CORS 설정 — WebConfig

📖 CORS(Cross-Origin Resource Sharing)란?

브라우저는 보안 때문에 지금 페이지와 출처(프로토콜 + 도메인 + 포트)가 다른 서버로 보내는 요청의 응답을 기본적으로 막는다. React(localhost:5173)와 Spring Boot(localhost:8080)는 포트가 달라 출처가 다르다. 그래서 서버가 “5173에서 온 요청은 허용한다”고 응답 헤더로 알려 줘야 한다.

💡 config/WebConfig.java
package com.springboot.jpabook.config;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOrigins("http://localhost:5173") // React(Vite) 개발 서버
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")
                .allowCredentials(true)
                .maxAge(3600);
    }
}
설정의미
addMapping("/api/**")/api로 시작하는 모든 URL에 적용
allowedOrigins("http://localhost:5173")React 개발 서버 주소만 허용
allowedMethods(...)허용할 HTTP 메서드 — OPTIONS는 브라우저가 먼저 보내는 사전 요청(preflight)
allowedHeaders("*")Content-Type: application/json 등 모든 요청 헤더 허용
allowCredentials(true)쿠키 · 인증 정보 포함 허용 (로그인 기능을 붙일 때 필요)
maxAge(3600)사전 요청 결과를 1시간 동안 브라우저가 기억
🖥️ CORS 설정이 없을 때 — 브라우저 F12 Console
Access to XMLHttpRequest at 'http://localhost:8080/api/posts' from origin 'http://localhost:5173' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource.
📌 Postman은 되는데 React는 안 될 때 Postman은 브라우저가 아니라서 CORS 검사를 하지 않는다. 그래서 Postman에서는 되는데 React에서는 안 되는 경우가 바로 CORS 문제다.

타입용도서버 DTO와 비교

4-3. API 함수 — api/posts.ts

💡 src/api/posts.ts
import api from "./api";
import type { Post, PostForm, PostUpdateForm } from "../types/post";

interface PostRow{
  id: number;
  title: string;
  writer: string;
  content: string;
  createdAt: string;
  updatedAt: string;
}

// 서버 모양 -> 화면 모양
const toPost = (row: PostRow): Post => ({
  id: row.id,
  title: row.title,
  writer: row.writer,
  content: row.content,
  createdAt: row.createdAt,
  updatedAt: row.updatedAt
})

// 글 목록 조회
export const getPosts = async () => {
  const response = await api.get<PostRow[]>('/posts');
  return response.data.map(toPost);
}

// 글 추가
export const createPost = async (form: PostForm) => {
  const response = await api.post<PostRow>('/posts', form);
  return toPost(response.data);
}

// 글 수정
export const updatePost = async (id: number, form: PostUpdateForm) => {
  const response = await api.put<PostRow>(`/posts/${id}`, form);
  return toPost(response.data);
}

// 글 삭제 (서버는 응답 본문 없이 200 OK)
export const deletePost = async (id: number) => {
  await api.delete(`/posts/${id}`);
}
함수요청반환
getPosts()GET /api/postsPost[]
createPost(form)POST /api/posts + JSON저장된 Post
updatePost(id, form)PUT /api/posts/{id} + JSON수정된 Post
deletePost(id)DELETE /api/posts/{id}없음 (200 OK)
💡 async / await async 함수 안에서 await는 서버 응답이 올 때까지 기다린다. axios는 응답 JSON을 response.data에 객체로 넣어 준다. toPost()는 서버 모양(PostRow)을 화면 모양(Post)으로 바꾸는 자리로, 나중에 필드 이름이 달라져도 여기만 고치면 된다.

📖 왜 Context인가?

목록 · 상세 · 메인 · 수정 화면이 모두 같은 글 목록을 쓴다. 화면마다 따로 불러오지 않고 PostProvider가 한 번 불러와 보관하고, 각 화면은 usePost()로 꺼내 쓴다.

5-1. PostContext.ts — 통로와 사용 함수

💡 src/context/PostContext.ts
import { createContext, useContext } from 'react';
import type { Post, PostForm, PostUpdateForm } from '../types/post'

interface PostContextType{
  posts: Post[];
  isLoading: boolean;   // 글 목록 불러오는 중
  addPost: (form: PostForm) => Promise<Post>;   // 글 추가
  editPost: (id: number, form: PostUpdateForm) => Promise<Post>;   // 글 수정
  removePost: (id: number) => Promise<void>;   // 글 삭제
}

export const PostContext = createContext<PostContextType | null>(null);

export const usePost = () => {
  const context = useContext(PostContext);
  if(!context){
    throw new Error("usePost는 PostProvider 내부에서만 사용 가능")
  }
  return context;
}
📌 usePost usePost()는 useContext를 감싼 사용자 정의 Hook이다. Provider 밖에서 쓰면 바로 오류를 내서 실수를 빨리 찾게 한다.

5-2. PostProvider.tsx — 상태와 CRUD 함수

💡 src/context/PostProvider.tsx
import React, { useEffect, useState } from "react";
import { PostContext } from "./PostContext";
import type { Post, PostForm, PostUpdateForm } from "../types/post";
import { createPost, deletePost, getPosts, updatePost } from "../api/posts";

const PostProvider = ({children}: {children: React.ReactNode}) => {
  // 게시글 상태 관리
  const [posts, setPosts] = useState<Post[]>([]);
  const [isLoading, setIsLoading] = useState(true);   // 처음엔 불러오는 중

  // 화면이 첫 렌더링 될대 글 목록 가져옴
  useEffect(() => {
    getPosts()
      .then(setPosts)
      .catch(err => console.log("글 목록 조회 오류!", err))
      .finally(() => setIsLoading(false));   // 성공/실패 상관없이 로딩 끝
  },[])

  // 글 추가: 서버에 저장 후, 저장된 글을 목록 상태에 반영
  const addPost = async (form: PostForm) => {
    const saved = await createPost(form);
    setPosts(prev => [saved, ...prev]);   // 서버 목록이 id 내림차순이므로 맨 앞에 추가
    return saved;
  }

  // 글 수정: 서버에 저장 후, 같은 id의 글을 수정된 글로 교체
  const editPost = async (id: number, form: PostUpdateForm) => {
    const updated = await updatePost(id, form);
    setPosts(prev => prev.map(p => (p.id === id ? updated : p)));
    return updated;
  }

  // 글 삭제: 서버에서 삭제 후, 목록 상태에서 제거
  const removePost = async (id: number) => {
    await deletePost(id);
    setPosts(prev => prev.filter(p => p.id !== id));
  }

  return(
    <PostContext.Provider value={{
      posts,
      isLoading,
      addPost,
      editPost,
      removePost,
    }}>
      {children}
    </PostContext.Provider>
  )
}

export default PostProvider;
코드의미
useState<Post[]>([])글 목록 상태 (처음엔 빈 배열)
useEffect(() => {...}, [])화면이 처음 그려질 때 한 번 서버에서 목록을 가져온다
.finally(() => setIsLoading(false))성공 · 실패와 상관없이 로딩 끝
setPosts(prev => [saved, ...prev])새 글을 맨 앞에 추가 (서버 목록이 최신순)
prev.map(p => p.id === id ? updated : p)같은 id의 글만 수정된 글로 교체
prev.filter(p => p.id !== id)삭제한 글만 빼고 새 배열
💡 불변성 상태를 바꿀 때는 기존 배열을 직접 고치지 않고 새 배열을 만든다(... 펼침, map, filter). 그래야 React가 바뀐 것을 알고 화면을 다시 그린다.

const PostWrite = () => {
  const { addPost } = usePost();
  const navigate = useNavigate();

  const [form, setForm] = useState<PostForm>({ title: "", writer: "", content: "" });
  const [submitting, setSubmitting] = useState(false);

    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  }

  // 등록
  const handleSubmit = async (e: React.SubmitEvent<HTMLFormElement>) => {

    if (!form.title.trim())   return alert("제목을 입력하세요.");
    if (!form.writer.trim())  return alert("글쓴이를 입력하세요.");
    if (!form.content.trim()) return alert("내용을 입력하세요.");

    try {
      setSubmitting(true);
      await addPost(form);
      navigate("/posts");
    } catch (err) {
      console.log("글 등록 오류!", err);
      alert("글 등록에 실패했습니다.");
      setSubmitting(false);
    }
  }

  return (
    <PostWriteForm
      form={form}
      submitting={submitting}
      onChange={handleChange}
      onSubmit={handleSubmit}
    />
  )
}

    setForm(prev => ({ ...prev, [name]: value }));
  }

  const handleSubmit = async (e: React.SubmitEvent<HTMLFormElement>) => {
    e.preventDefault();

    if (!form.title.trim())   return alert("제목을 입력하세요.");
    if (!form.content.trim()) return alert("내용을 입력하세요.");

    try {
      setSubmitting(true);
      // 서버는 제목/내용만 수정
      await editPost(post.id, { title: form.title, content: form.content });
      navigate(`/posts/${post.id}`);
    } catch (err) {
      console.log("글 수정 오류!", err);
      alert("글 수정에 실패했습니다.");
      setSubmitting(false);
    }
  }

  return (
    <PostWriteForm
      form={form}
      submitting={submitting}
      onChange={handleChange}
      onSubmit={handleSubmit}
      heading="글 수정"
      submitLabel="수정"
      cancelTo={`/posts/${post.id}`}
      writerReadOnly
    />
  )
}


const PostEdit = () => {
  const { id } = useParams<{ id: string }>();
  const { posts, isLoading } = usePost();

  const post = posts.find(p => p.id === Number(id));

  if (isLoading) {
    return (
      <div className="post-detail">
        <p className="post-empty">불러오는 중...</p>
      </div>
    )
  }

  if (!post) {
    return (
      <div className="post-detail">
        <p className="post-empty">글을 찾을 수 없습니다.</p>
        <div className="post-actions">
          <Link to="/posts" className="btn">목록</Link>
        </div>
      </div>
    )
  }

  // key: 다른 글로 이동하면 폼 상태를 새로 만들기 위함
  return <PostEditForm key={post.id} post={post} />;
}

export default PostEdit;
📌 key로 폼 초기화 <PostEditForm key={post.id} …> — key가 바뀌면 React가 컴포넌트를 새로 만든다. 다른 글의 수정 화면으로 이동했을 때 이전 글의 입력값이 남지 않게 한다. 목록을 불러오는 중에는 글이 없으므로 PostEdit가 로딩 · 없음을 먼저 처리하고, 글이 있을 때만 폼을 만든다.

10-3. 자주 만나는 오류

⚠️ 오류와 해결
  • blocked by CORS policy — WebConfig가 없거나 allowedOrigins 주소(포트)가 다르다. Vite가 5174 등 다른 포트로 떴는지 확인.
  • Network Error / ERR_CONNECTION_REFUSED — Spring Boot 서버가 꺼져 있다 (8080).
  • 목록이 계속 “불러오는 중…” — F12 → Console · Network 탭에서 /api/posts 요청의 상태 코드 확인.
  • 400 · 값이 null로 저장 — JSON 키 이름(title · writer · content)이 서버 DTO 필드와 다르다.
  • 500 not found: id — 없는 id를 수정 · 조회했다 (서버 콘솔에 IllegalArgumentException).
  • npm 명령을 찾을 수 없음 — Node.js 설치 후 명령 프롬프트 · VS Code를 다시 연다.
