1-2. 세션 방식 vs JWT 방식 — 어느 탭으로 배울까

A. 세션 방식 (이 탭)B. JWT 방식 (다음 탭)

CSRF켬 — 쿠키를 자동으로 보내므로 필요끔 — 토큰을 직접 붙이므로 불필요
로그아웃서버에 요청 → 세션 삭제토큰만 지우면 끝

어울리는 곳같은 회사 서버 · 웹 화면 하나모바일 앱 · 여러 서버 · 외부 API
💡 수업 순서 처음에는 A(세션)로 React와 서버를 붙여 보고, 다음 시간에 B(JWT)로 같은 화면을 토큰 방식으로 바꿔 보면 두 방식의 차이가 잘 보인다. 두 탭은 각각 처음부터 끝까지 완성되므로 하나만 해도 된다. 관리자 · AI · 배포 탭은 두 방식 모두에서 쓸 수 있게 차이를 함께 적었다.

2-2. ApiExceptionHandler — 오류를 JSON으로

💡 controller/ApiExceptionHandler.java
@RestControllerAdvice   // 모든 REST 컨트롤러의 예외를 여기서 처리
public class ApiExceptionHandler {

    // 잘못된 요청 (없는 글 · 아이디 중복 · 빈 값) → 400
    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<Map<String, String>> handleBadRequest(IllegalArgumentException e) {
        return ResponseEntity.badRequest().body(Map.of("message", e.getMessage()));
    }

    // 로그인 실패 → 401
    @ExceptionHandler(BadCredentialsException.class)
    public ResponseEntity<Map<String, String>> handleLoginFail(BadCredentialsException e) {
        return ResponseEntity.status(HttpStatus.UNAUTHORIZED).body(Map.of("message", e.getMessage()));
    }

    // 본인 글이 아님 (6장 PostService.checkWriter) → 403
    @ExceptionHandler(AccessDeniedException.class)
    public ResponseEntity<Map<String, String>> handleForbidden(AccessDeniedException e) {
        return ResponseEntity.status(HttpStatus.FORBIDDEN).body(Map.of("message", e.getMessage()));
    }
}
예외던지는 곳응답
IllegalArgumentExceptionPostService.findById() · UserService.save()400 {"message": "이미 사용 중인 아이디입니다."}
BadCredentialsException6단원 로그인 (AuthenticationManager)401 {"message": "…"}

3-2. vite.config.ts — /api를 8080으로 (프록시)

💡 vite.config.ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      // React(5173)에서 /api 로 보낸 요청 → Spring Boot(8080)로 전달
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
      },
    },
  },
});

📖 프록시를 쓰는 이유

브라우저는 localhost:5173에서 받은 화면이 localhost:8080으로 요청하면 다른 출처로 보고 막는다(CORS). 세션 쿠키 · CSRF 쿠키까지 주고받으려면 서버 · 화면 양쪽에 설정이 많이 늘어난다.

프록시를 쓰면 React는 자기 주소(/api/posts)로만 요청하고, Vite 개발 서버가 뒤에서 8080으로 넘겨 준다. 브라우저 입장에서는 같은 출처이므로 CORS 설정이 필요 없고, 쿠키도 그냥 붙는다.

4-3. API 함수 — api/posts.ts

💡 src/api/posts.ts
import api from './api';
import type { Post, PostForm, SearchType } from '../types/post';

// 목록 · 검색 — GET /api/posts?type=title&keyword=가입
export async function getPosts(type?: SearchType, keyword?: string): Promise<Post[]> {
  const response = await api.get<Post[]>('/posts', { params: { type, keyword } });
  return response.data;
}

// 상세 — GET /api/posts/{id}
export async function getPost(id: number): Promise<Post> {
  const response = await api.get<Post>(`/posts/${id}`);
  return response.data;
}

// 등록 — POST /api/posts (토큰 필요)
export async function createPost(form: PostForm): Promise<Post> {
  const response = await api.post<Post>('/posts', form);
  return response.data;
}

// 수정 — PUT /api/posts/{id} (본인)
export async function updatePost(id: number, form: PostForm): Promise<Post> {
  const response = await api.put<Post>(`/posts/${id}`, form);
  return response.data;
}

// 삭제 — DELETE /api/posts/{id} (본인)
export async function deletePost(id: number): Promise<void> {
  await api.delete(`/posts/${id}`);
}
코드의미
api.get<Post[]>(…)응답 데이터의 타입을 알려 준다 → response.data가 Post[]
{ params: { type, keyword } }주소 뒤에 ?type=…&keyword=…. 값이 undefined면 빠진다 → 전체 목록
createPost · updatePost · deletePost지금 함께 만들어 두고, 글쓰기 단원에서 쓴다

export default function PostList() {
  // 주소의 ?type=title&keyword=가입 읽기
  const [searchParams, setSearchParams] = useSearchParams();
  const type = (searchParams.get('type') ?? 'title') as SearchType;
  const keyword = searchParams.get('keyword') ?? '';

  const [posts, setPosts] = useState<Post[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  // 검색 폼 입력값
  const [inputType, setInputType] = useState<SearchType>(type);
  const [inputKeyword, setInputKeyword] = useState(keyword);

  // 주소의 type · keyword가 바뀔 때마다 다시 불러온다
  useEffect(() => {
    getPosts(type, keyword)
      .then(setPosts)
      .finally(() => setIsLoading(false));
  }, [type, keyword]);

  const handleSearch = (e: FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    if (inputKeyword.trim()) {
      setSearchParams({ type: inputType, keyword: inputKeyword.trim() });
    } else {
      setSearchParams({});            // 검색어가 없으면 전체 목록

  };

    setInputType('title');
    setInputKeyword('');
    setSearchParams({});
  };

  return (

      {/* 검색 */}
      <form onSubmit={handleSearch} className="row g-2 justify-content-end mb-3">
        <div className="col-auto">
          <select className="form-select" value={inputType}

          </select>
        </div>

        </div>
        <div className="col-auto">
          <button type="submit" className="btn btn-outline-primary me-1">검색</button>
          <button type="button" className="btn btn-outline-secondary" onClick={handleReset}>초기화</button>
        </div>
      </form>

      <div className="d-flex justify-content-between align-items-center mb-3">
        <span>전체 {posts.length}건</span>
        <Link to="/posts/new" className="btn btn-primary">글쓰기</Link>
      </div>

        <thead className="table-light">
          <tr>
            <th style={{ width: 80 }}>번호</th>
            <th>제목</th>

        </tbody>

    </>
  );

useSearchParams()주소의 ?type=…&keyword=…를 읽고 바꾸는 Hook — 5장 ${param.keyword}와 같은 역할

💡 config/SecurityConfig.java
package com.springboot.boardweb.config;

import com.springboot.boardweb.service.UserDetailService;
import lombok.RequiredArgsConstructor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.http.HttpStatus;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.ProviderManager;
import org.springframework.security.authentication.dao.DaoAuthenticationProvider;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.HttpStatusEntryPoint;
import org.springframework.security.web.authentication.logout.HttpStatusReturningLogoutSuccessHandler;

@RequiredArgsConstructor
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    private final UserDetailService userDetailService;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http){
        http
            // ① CSRF — 켜 두고, 토큰을 XSRF-TOKEN 쿠키로 내려 준다 (React · axios용)
            .csrf(csrf -> csrf.spa())
            // ② 로그인 화면 · 팝업 끄기 — 6단원 JSON 로그인 API가 맡는다
            .formLogin(AbstractHttpConfigurer::disable)
            .httpBasic(AbstractHttpConfigurer::disable)
            // ③ 경로별 권한 (6장과 같다)
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**", "/error").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/posts/**").permitAll()
                .anyRequest().authenticated()  //나머지는 로그인 필요
            )
            // ④ 로그인 안 했으면 로그인 화면(302) 대신 401
            .exceptionHandling(e -> e
                .authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED)))
            // ⑤ 로그아웃 API — POST /api/auth/logout → 세션 삭제 → 200
            .logout(logout -> logout
                .logoutUrl("/api/auth/logout")
                .logoutSuccessHandler(new HttpStatusReturningLogoutSuccessHandler()));
        return http.build();
    }

    // 6단원 로그인 API에서 아이디 · 비밀번호를 확인할 도구
    @Bean
    public AuthenticationManager authenticationManager(PasswordEncoder passwordEncoder) {
        DaoAuthenticationProvider provider = new DaoAuthenticationProvider(userDetailService);
        provider.setPasswordEncoder(passwordEncoder);   // BCrypt로 비교
        return new ProviderManager(provider);
    }

    // 비밀번호 암호화 도구(UserService에서 주입받아 사용)
    @Bean
    public PasswordEncoder passwordEncoder(){
        return new BCryptPasswordEncoder();
    }
}
설정6장 (Thymeleaf)이 탭 (React · 세션)
csrf켬 — <meta> 태그로 토큰 전달켬 — csrf.spa(): 토큰을 XSRF-TOKEN 쿠키로 → axios가 자동으로 X-XSRF-TOKEN 헤더에 넣는다
formLogin/login 화면 · 폼 전송disable — JSON 로그인 API(6단원)
세션사용사용 (그대로) — STATELESS 설정 없음
로그인 안 한 요청로그인 화면으로 이동 (302)401 — React가 받아 로그인 화면으로
로그아웃POST /logout → 메인으로 이동POST /api/auth/logout → 200
AuthenticationManager시큐리티가 안에서 사용빈으로 등록 — 로그인 API가 직접 호출

📖 csrf.spa() — React에서 CSRF 쓰기

  • 6장은 Thymeleaf가 화면에 <meta name="_csrf">로 토큰을 넣어 주었다. React는 서버가 화면을 만들지 않으므로 이 방법을 쓸 수 없다.
  • csrf.spa()는 토큰을 XSRF-TOKEN 쿠키로 내려 준다. axios는 같은 주소로 요청할 때 이 쿠키를 읽어 X-XSRF-TOKEN 헤더에 자동으로 넣는다 — 화면 코드에 CSRF 코드가 한 줄도 필요 없다.
  • 다른 사이트의 스크립트는 우리 쿠키를 읽을 수 없어서 헤더를 만들지 못한다 → CSRF 공격이 막힌다.
📌 CORS 없음 CORS 설정은 넣지 않는다. 3단원의 Vite 프록시 덕분에 브라우저는 React(5173)와 API를 같은 주소로 본다. 쿠키 · CSRF가 가장 간단하게 동작하는 구성이다.
⚠️ import 주의 DaoAuthenticationProvider는 org.springframework.security.authentication.dao, HttpStatusEntryPoint는 …web.authentication, HttpStatusReturningLogoutSuccessHandler는 …web.authentication.logout 패키지다. 위 import를 그대로 쓴다.

import org.springframework.security.core.Authentication;

// 화면에 보여 줄 로그인 사용자 정보 (record — 9장 부록)

💡 controller/AuthApiController.java
package com.springboot.boardweb.controller;

import com.springboot.boardweb.dto.AddUserRequest;
import com.springboot.boardweb.dto.LoginRequest;
import com.springboot.boardweb.dto.UserInfoResponse;
import com.springboot.boardweb.service.UserService;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContext;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.web.context.HttpSessionSecurityContextRepository;
import org.springframework.security.web.context.SecurityContextRepository;
import org.springframework.security.web.csrf.CsrfToken;
import org.springframework.web.bind.annotation.*;

@RequiredArgsConstructor
@RequestMapping("/api/auth")
@RestController
public class AuthApiController {
    private final UserService userService;
    private final AuthenticationManager authenticationManager;   // 5단원 빈
    // 로그인 정보를 세션에 저장하는 도구
    private final SecurityContextRepository securityContextRepository =
            new HttpSessionSecurityContextRepository();

    // ① 회원가입 → POST /api/auth/signup (6장 save() 재사용)
    @PostMapping("/signup")
    public ResponseEntity<Void> signup(@RequestBody AddUserRequest request) {
        userService.save(request);
        return ResponseEntity.status(HttpStatus.CREATED).build();
    }

    // ② 로그인 → POST /api/auth/login → 세션에 저장
    @PostMapping("/login")
    public ResponseEntity<UserInfoResponse> login(@RequestBody LoginRequest request,
                                                  HttpServletRequest httpRequest,
                                                  HttpServletResponse httpResponse) {
        // 아이디 · 비밀번호 확인 — 틀리면 BadCredentialsException → 401 (2단원)
        Authentication authentication = authenticationManager.authenticate(
                UsernamePasswordAuthenticationToken.unauthenticated(
                        request.getUsername(), request.getPassword()));

        // 세션 고정 공격 방지 — 로그인 전에 쓰던 세션 ID를 새 것으로
        if (httpRequest.getSession(false) != null) {
            httpRequest.changeSessionId();
        }

        // 로그인 정보를 SecurityContext에 담아 세션에 저장
        SecurityContext context = SecurityContextHolder.createEmptyContext();
        context.setAuthentication(authentication);
        SecurityContextHolder.setContext(context);
        securityContextRepository.saveContext(context, httpRequest, httpResponse);

        return ResponseEntity.ok(UserInfoResponse.from(authentication));
    }

    // ③ 내 정보 → GET /api/auth/me (React가 새로고침할 때마다 호출)
    @GetMapping("/me")
    public ResponseEntity<UserInfoResponse> me(Authentication authentication, CsrfToken csrfToken) {
        csrfToken.getToken();          // 토큰을 한 번 읽으면 XSRF-TOKEN 쿠키가 응답에 실린다
        if (authentication == null) {
            return ResponseEntity.noContent().build();          // 204 — 로그인 안 함
        }
        return ResponseEntity.ok(UserInfoResponse.from(authentication));   // 200 + 아이디 · 권한
    }

    // ④ 로그아웃 → POST /api/auth/logout — 5단원 SecurityConfig의 logout()이 처리 (메서드 없음)
}
코드의미
authenticationManager.authenticate(…)6장에서 폼 로그인이 안에서 하던 일 — UserDetailService로 회원을 찾고 BCrypt로 비밀번호 비교
UsernamePasswordAuthenticationToken.unauthenticated(…)“아직 확인 전”인 아이디 · 비밀번호 묶음
changeSessionId()로그인 순간 세션 ID를 바꿔, 로그인 전에 누가 심어 둔 세션 ID를 쓸모없게 만든다
securityContextRepository.saveContext(…)로그인 정보를 세션에 저장 → 응답에 JSESSIONID 쿠키. 다음 요청부터 시큐리티가 세션에서 꺼내 Principal로 넣어 준다
Authentication authentication (me)로그인했으면 사용자 정보, 안 했으면 null
CsrfToken csrfToken현재 CSRF 토큰. getToken()을 부르면 XSRF-TOKEN 쿠키가 응답에 들어간다 → React가 첫 POST 전에 받아 둔다
204 No Content“로그인 안 됨”을 오류(401)가 아닌 빈 응답으로 — React가 조용히 로그아웃 상태로 시작한다
⚠️ saveContext() 빼먹지 않기 Spring Security 6부터는 직접 로그인 처리를 할 때 세션 저장을 스스로 해야 한다. saveContext()를 빼면 로그인 응답은 200인데, 바로 다음 요청에서 다시 401이 난다(로그인이 유지되지 않음).
▶ 서버 확인 브라우저 주소창에 http://localhost:8080/api/auth/me → 빈 화면(204)이면 정상. F12 → Application → Cookies에 XSRF-TOKEN이 생긴다. 로그인 · 글쓰기는 POST라 CSRF 토큰이 필요하므로, 확인은 React 화면(10단원)에서 한다.

📖 왜 Context API인가 — 로그인 상태 vs 게시글 데이터

  • 로그인 상태는 여러 화면이 함께 쓴다 — Header(아이디 · 로그아웃) · PrivateRoute(접근 막기) · PostDetail(본인 글) · AdminRoute(관리자). props로 넘기면 App → 중간 컴포넌트 → 사용처로 줄줄이 전달해야 한다(prop drilling). Context는 useAuth() 한 줄.
  • 자주 바뀌지 않는다 — 로그인 · 로그아웃 때만 바뀌므로, “값이 바뀌면 쓰는 화면이 모두 다시 그려진다”는 Context의 약점이 거의 문제 되지 않는다.
  • 게시글 목록 · 상세는 Context에 넣지 않는다 — 화면마다 서버에서 받아 따로 쓰는 데이터라 각 화면의 useEffect로 불러온다. Context에 넣으면 목록이 바뀔 때 Header까지 다시 그려지고, 언제 다시 불러올지 직접 관리해야 한다.
  • React 기본 기능이라 라이브러리 설치가 필요 없다.
방법언제이 교안에서
Context API로그인 · 테마 · 언어처럼 앱 전체가 쓰고 가끔 바뀌는 값⭕ 로그인 상태
props 전달부모 → 자식 한두 단계⭕ AiAssistant의 title · onSelect (AI 탭)
Zustand · Redux Toolkit전역 상태가 많고 자주 바뀌는 큰 앱소개만
TanStack Query (React Query)서버 데이터의 캐시 · 재요청 · 로딩 관리소개만 — 게시글 불러오기를 대신할 수 있다
💡 React 19 새 문법 React 19에서는 <AuthContext.Provider value={…}> 대신 <AuthContext value={…}>, useContext(AuthContext) 대신 use(AuthContext)로도 쓸 수 있다. 자료가 많은 .Provider · useContext를 기본으로 쓰고, 새 문법은 알아만 둔다.

7-2. AuthContext.ts — 통로와 useAuth()

💡 src/context/AuthContext.ts
import { createContext, useContext } from 'react';
import type { AuthForm } from '../types/auth';

export interface AuthContextType {
  username: string | null;                    // 로그인 아이디 (로그인 전 null)
  role: string | null;                        // 'USER' | 'ADMIN'
  isLoggedIn: boolean;
  isAdmin: boolean;
  loading: boolean;                           // 서버에 로그인 상태를 묻는 중
  login: (form: AuthForm) => Promise<void>;
  logout: () => Promise<void>;                // 서버에 요청하므로 async
}

export const AuthContext = createContext<AuthContextType | null>(null);

// 화면에서 로그인 상태를 꺼내 쓰는 Hook
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth는 AuthProvider 안에서만 사용할 수 있습니다.');
  }
  return context;
}

7-3. AuthProvider.tsx — me · login · logout

💡 src/context/AuthProvider.tsx
import { useEffect, useState } from 'react';
import type { ReactNode } from 'react';
import { AuthContext } from './AuthContext';
import { login as loginApi, logout as logoutApi, me } from '../api/auth';
import type { AuthForm, UserInfo } from '../types/auth';

export default function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<UserInfo | null>(null);
  const [loading, setLoading] = useState(true);

  // ① 처음 열릴 때(새로고침 포함) — 서버에 “나 로그인했나?” 묻기 (+ CSRF 쿠키 받기)
  useEffect(() => {
    me()
      .then(setUser)
      .finally(() => setLoading(false));
  }, []);

  // ② 로그인 — 서버가 세션에 저장 → 내 정보 다시 받기
  const login = async (form: AuthForm) => {
    await loginApi(form);                  // POST /api/auth/login
    setUser(await me());                   // GET /api/auth/me
  };

  // ③ 로그아웃 — 서버 세션 삭제 → 새 CSRF 쿠키 받기
  const logout = async () => {
    await logoutApi();                     // POST /api/auth/logout
    setUser(null);
    await me();                            // 로그아웃 때 지워진 XSRF-TOKEN 쿠키를 다시 받는다
  };

  return (
    <AuthContext.Provider value={{
      username: user?.username ?? null,
      role: user?.role ?? null,
      isLoggedIn: user !== null,
      isAdmin: user?.role === 'ADMIN',
      loading, login, logout,
    }}>
      {children}
    </AuthContext.Provider>
  );
}

useEffect(() => me()…, [])React 상태는 새로고침하면 사라진다 → 서버 세션에 물어 다시 채운다 (JWT는 localStorage에서 읽음)
loadingme() 응답 전에는 로그인 여부를 모른다 — 이때 7-5 PrivateRoute가 로그인 화면으로 잘못 보내지 않게 막는다
setUser(await me())로그인 성공 후 서버 기준 정보로 상태를 채운다
await me() (로그아웃 후)로그아웃하면 시큐리티가 XSRF-TOKEN 쿠키도 지운다 → 새 토큰을 받아야 다음 로그인(POST)이 403이 나지 않는다

import { useEffect, useState } from 'react';
import type { ChangeEvent, FormEvent } from 'react';
import { useNavigate, useParams } from 'react-router-dom';
import { createPost, getPost, updatePost } from '../api/posts';
import { getErrorMessage } from '../api/api';
import type { PostForm } from '../types/post';

export default function PostWrite() {
  const { id } = useParams();                 // /posts/3/edit → "3", /posts/new → undefined
  const isEdit = id !== undefined;            // id가 있으면 수정
  const navigate = useNavigate();
  const [form, setForm] = useState<PostForm>({ title: '', content: '' });
  const [saving, setSaving] = useState(false);

  // 수정이면 기존 글을 불러와 폼에 채운다
  useEffect(() => {
    if (!isEdit) return;
    getPost(Number(id))
      .then(post => setForm({ title: post.title, content: post.content }));
  }, [id, isEdit]);

  const handleChange = (e: ChangeEvent<HTMLInputElement | HTMLTextAreaElement>) => {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  };

  const handleSubmit = async (e: FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    if (!form.title.trim()) {
      alert('제목을 입력하세요.');
      return;
    }
    setSaving(true);                          // 저장 중 버튼 막기 (두 번 누르기 방지)
    try {
      if (isEdit) {
        await updatePost(Number(id), form);   // PUT /api/posts/{id}
        alert('수정되었습니다.');
        navigate(`/posts/${id}`, { replace: true });
      } else {
        const saved = await createPost(form); // POST /api/posts
        alert('등록되었습니다.');
        navigate(`/posts/${saved.id}`, { replace: true });
      }
    } catch (err) {
      alert(getErrorMessage(err));            // 403 · 400 문구
      setSaving(false);
    }
  };

  return (
    <div className="mx-auto" style={{ width: '60%' }}>
      <h2 className="mb-4">{isEdit ? '글 수정' : '글쓰기'}</h2>
      <form onSubmit={handleSubmit}>
        <div className="mb-3">
          <label htmlFor="title" className="form-label">제목</label>
          <input id="title" name="title" className="form-control"
                 value={form.title} onChange={handleChange} />
        </div>
        <div className="mb-3">
          <label htmlFor="content" className="form-label">글내용</label>
          <textarea id="content" name="content" className="form-control" rows={10}
                    value={form.content} onChange={handleChange} />
        </div>
        <button type="submit" className="btn btn-primary me-1" disabled={saving}>
          {isEdit ? '수정' : '등록'}
        </button>
        <button type="button" className="btn btn-secondary" onClick={() => navigate(-1)}>취소</button>
      </form>
    </div>
  );
}

1-2. 세션 방식(6장) vs JWT 방식

📖 왜 JWT로 바꾸나

6장의 폼 로그인은 서버가 화면(HTML)을 만들고, 로그인 정보를 서버 세션에 저장한 뒤 브라우저에 쿠키(JSESSIONID)를 준다. React는 화면을 직접 그리고 서버와는 JSON만 주고받으므로, 로그인 결과도 화면 이동이 아니라 JSON(토큰)으로 받는 방식이 잘 맞는다.

세션 방식 (6장)JWT 방식 (이 교안)
로그인 정보 저장서버 메모리(세션)토큰 안에 아이디 · 만료 시각을 담아 클라이언트가 보관

        config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        config.setAllowedHeaders(List.of("*"));          // Authorization 헤더 포함

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/api/**", config);
        return source;
    }

📖 CORS란?

브라우저는 화면을 받은 주소(localhost:5173)와 다른 주소(localhost:8080)로 보내는 요청의 응답을 기본으로 막는다(동일 출처 정책). 포트만 달라도 다른 출처다. 서버가 “5173에서 오는 요청은 허용한다”고 응답 헤더로 알려 줘야 React가 응답을 읽을 수 있다.

헤더에 Authorization을 붙이면 브라우저는 본 요청 전에 OPTIONS 요청(preflight)으로 먼저 허락을 묻는다. 그래서 허용 메서드에 OPTIONS를 넣는다.

⚠️ CORS는 시큐리티에서 WebMvcConfigurer.addCorsMappings()만 쓰면 preflight 요청이 시큐리티 필터에서 먼저 막혀 401이 날 수 있다. 시큐리티를 쓸 때는 .cors(Customizer.withDefaults()) + CorsConfigurationSource 빈으로 설정한다. import는 org.springframework.web.cors.* · org.springframework.security.config.Customizer.
📌 지금은 읽기만 지금은 6장 세션 설정 그대로라 GET /api/posts/**만 로그인 없이 열려 있다 → 4단원 읽기 화면은 이것으로 충분하다. 8단원에서 SecurityConfig 전체를 JWT용으로 다시 쓸 때 이 CORS 설정도 함께 들어간다.

// 상세 — GET /api/posts/{id}

export async function updatePost(id: number, form: PostForm): Promise<Post> {

  return response.data;
}

export async function deletePost(id: number): Promise<void> {

import { useEffect, useState } from 'react';
import type { FormEvent } from 'react';
import { Link, useSearchParams } from 'react-router-dom';
import dayjs from 'dayjs';
import { getPosts } from '../api/posts';
import type { Post, SearchType } from '../types/post';

export default function PostList() {
  // 주소의 ?type=title&keyword=가입 읽기
  const [searchParams, setSearchParams] = useSearchParams();
  const type = (searchParams.get('type') ?? 'title') as SearchType;
  const keyword = searchParams.get('keyword') ?? '';

  const [posts, setPosts] = useState<Post[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  // 검색 폼 입력값
  const [inputType, setInputType] = useState<SearchType>(type);
  const [inputKeyword, setInputKeyword] = useState(keyword);

  // 주소의 type · keyword가 바뀔 때마다 다시 불러온다
  useEffect(() => {
    getPosts(type, keyword)
      .then(setPosts)
      .finally(() => setIsLoading(false));
  }, [type, keyword]);

  const handleSearch = (e: FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    if (inputKeyword.trim()) {
      setSearchParams({ type: inputType, keyword: inputKeyword.trim() });
    } else {
      setSearchParams({});            // 검색어가 없으면 전체 목록
    }
  };

  const handleReset = () => {
    setInputType('title');
    setInputKeyword('');
    setSearchParams({});
  };

  return (
    <>
      {/* 검색 */}
      <form onSubmit={handleSearch} className="row g-2 justify-content-end mb-3">
        <div className="col-auto">
          <select className="form-select" value={inputType}
                  onChange={e => setInputType(e.target.value as SearchType)}>
            <option value="title">제목</option>
            <option value="content">내용</option>
            <option value="writer">글쓴이</option>
          </select>
        </div>
        <div className="col-auto">
          <input className="form-control" placeholder="검색어를 입력하세요"
                 value={inputKeyword} onChange={e => setInputKeyword(e.target.value)} />
        </div>
        <div className="col-auto">
          <button type="submit" className="btn btn-outline-primary me-1">검색</button>
          <button type="button" className="btn btn-outline-secondary" onClick={handleReset}>초기화</button>
        </div>
      </form>

      <div className="d-flex justify-content-between align-items-center mb-3">
        <span>전체 {posts.length}건</span>
        <Link to="/posts/new" className="btn btn-primary">글쓰기</Link>
      </div>

      <table className="table table-hover">
        <thead className="table-light">
          <tr>
            <th style={{ width: 80 }}>번호</th>
            <th>제목</th>
            <th style={{ width: 120 }}>글쓴이</th>
            <th style={{ width: 170 }}>작성일</th>
          </tr>
        </thead>
        <tbody>
          {posts.map(post => (
            <tr key={post.id}>
              <td>{post.id}</td>
              <td><Link to={`/posts/${post.id}`}>{post.title}</Link></td>
              <td>{post.writer}</td>
              <td>{dayjs(post.createdAt).format('YYYY-MM-DD HH:mm')}</td>
            </tr>
          ))}
          {!isLoading && posts.length === 0 && (
            <tr>
              <td colSpan={4} className="text-center text-muted">
                {keyword ? '검색 결과가 없습니다.' : '등록된 글이 없습니다.'}
              </td>
            </tr>
          )}
        </tbody>
      </table>
    </>
  );
}
코드의미
useSearchParams()주소의 ?type=…&keyword=…를 읽고 바꾸는 Hook — 5장 ${param.keyword}와 같은 역할
setSearchParams({ type, keyword })주소가 바뀐다 → 새로고침 · 뒤로 가기에도 검색 유지
useEffect(…, [type, keyword])검색 조건이 바뀔 때마다 서버에 다시 요청
posts.map(post => <tr key={post.id}>)반복 (5장 th:each)
{조건 && (…)}조건이 참일 때만 그리기 (5장 th:if)
⚠️ “전체 건” — 숫자가 비면 { } 안의 값이 undefined · null · false이면 React는 아무것도 그리지 않고 오류도 내지 않는다. “전체 건”처럼 숫자가 비면 posts.length를 posts.count · posts.size(배열에 없음) · postCount(Home 변수)로 잘못 쓰지 않았는지 본다. VS Code의 빨간 밑줄 · npm run dev 터미널의 타입 오류를 먼저 확인한다.

5-1. JWT의 모양

📖 점(.)으로 나뉜 세 부분

JWT는 xxxxx.yyyyy.zzzzz처럼 점으로 나뉜 문자열 하나다. 각 부분은 Base64URL로 인코딩되어 있어 jwt.io에 붙여 넣으면 내용을 볼 수 있다.

부분내용 (예)설명
Header{"alg":"HS256"}서명 알고리즘
Payload{"sub":"hong","iat":1795100000,"exp":1795103600}sub = 아이디, iat = 발급 시각, exp = 만료 시각 (초)
SignatureHMACSHA256(header + "." + payload, 비밀키)서버만 아는 비밀키로 만든 서명 — 위조 검사용
💡 토큰 예 (줄바꿈은 보기 쉽게 넣은 것)
eyJhbGciOiJIUzI1NiJ9
.eyJzdWIiOiJob25nIiwiaWF0IjoxNzk1MTAwMDAwLCJleHAiOjE3OTUxMDM2MDB9
.4Xb9Gk2s1mVQd8t0Yw3c7pR5nL0qZ2hE6uJ9aK1sT3Q
⚠️ 토큰 내용은 누구나 읽는다 Payload는 암호화가 아니라 인코딩이다. 누구나 읽을 수 있으므로 비밀번호 같은 비밀 정보는 넣지 않는다. 대신 내용을 한 글자라도 바꾸면 서명이 맞지 않아 서버가 거부한다.

7 서버 ③ TokenProvider — 토큰 발급 · 검사

🎯 학습목표
  • 비밀키로 서명한 JWT를 발급하고, 토큰에서 아이디를 꺼낼 수 있다.
  • 위조 · 만료된 토큰을 가려낼 수 있다.
💡 config/jwt/TokenProvider.java
@Component
public class TokenProvider {
    private final SecretKey key;        // 서명용 비밀키
    private final long expiration;      // 유효 시간 (밀리초)

    // application.yml의 jwt.secret · jwt.expiration 읽기
    public TokenProvider(@Value("${jwt.secret}") String secret,
                         @Value("${jwt.expiration}") long expiration) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expiration = expiration;
    }

    // ① 토큰 발급 — 아이디를 담고 비밀키로 서명
    public String generateToken(String username) {
        Date now = new Date();
        return Jwts.builder()
                .subject(username)                                  // sub : 아이디
                .issuedAt(now)                                      // iat : 발급 시각
                .expiration(new Date(now.getTime() + expiration))   // exp : 만료 시각
                .signWith(key)                                      // 서명 (HS256)
                .compact();                                         // 문자열로
    }

    // ② 토큰에서 아이디 꺼내기 — 서명 · 만료 검사를 함께 한다
    public String getUsername(String token) {
        return Jwts.parser()
                .verifyWith(key)               // 같은 비밀키로 서명 확인
                .build()
                .parseSignedClaims(token)      // 위조 · 만료면 예외
                .getPayload()
                .getSubject();
    }

    // ③ 쓸 수 있는 토큰인가?
    public boolean validToken(String token) {
        try {
            getUsername(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;   // 서명 불일치 · 만료 · 형식 오류
        }
    }
}
코드의미
@Value("${jwt.secret}")application.yml 값을 생성자 매개변수로 받는다
Keys.hmacShaKeyFor(…)문자열 비밀키 → HMAC-SHA 서명용 키 객체 (32바이트 미만이면 WeakKeyException)
Jwts.builder() … .compact()토큰 만들기 → eyJ… 문자열
signWith(key)키 길이에 맞는 알고리즘(32바이트 → HS256)을 자동으로 고른다
Jwts.parser().verifyWith(key)받은 토큰을 같은 키로 검사
parseSignedClaims(token)서명이 틀리면 SignatureException, 만료면 ExpiredJwtException — 둘 다 JwtException
⚠️ import 주의 SecretKey는 javax.crypto.SecretKey, Date는 java.util.Date, Value는 org.springframework.beans.factory.annotation.Value를 import 한다. 롬복의 @Value를 고르면 설정값을 읽지 못한다.

8-1. TokenAuthenticationFilter — 요청마다 토큰 검사

💡 config/jwt/TokenAuthenticationFilter.java
@RequiredArgsConstructor
public class TokenAuthenticationFilter extends OncePerRequestFilter {
    private final TokenProvider tokenProvider;
    private final UserDetailService userDetailService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        // ① Authorization: Bearer eyJhbGci…
        String header = request.getHeader("Authorization");

        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);              // "Bearer " 뒤의 토큰만

            // ② 쓸 수 있는 토큰이면 → 이번 요청을 로그인 상태로
            if (tokenProvider.validToken(token)) {
                String username = tokenProvider.getUsername(token);
                UserDetails user = userDetailService.loadUserByUsername(username);
                Authentication authentication =
                        new UsernamePasswordAuthenticationToken(user, null, user.getAuthorities());
                SecurityContextHolder.getContext().setAuthentication(authentication);
            }
        }
        // ③ 다음 필터로 (토큰이 없어도 진행 — 권한 검사는 SecurityConfig 규칙이 한다)
        filterChain.doFilter(request, response);
    }
}

📌 2-4 CORS 포함 2-4에서 추가한 CORS 설정(.cors(…) · corsConfigurationSource())이 아래 완성 코드에 그대로 들어 있다. 이 코드로 파일 전체를 바꾼다.
💡 config/SecurityConfig.java
@RequiredArgsConstructor
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    private final TokenProvider tokenProvider;
    private final UserDetailService userDetailService;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http){
        http
            .csrf(AbstractHttpConfigurer::disable)          // 쿠키를 안 쓰므로 CSRF 끔
            .formLogin(AbstractHttpConfigurer::disable)     // 로그인 화면 없음 (API로 로그인)
            .httpBasic(AbstractHttpConfigurer::disable)
            .sessionManagement(session -> session
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS))   // 세션 안 만듦
            .cors(Customizer.withDefaults())                // 아래 CORS 설정 사용
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**", "/error").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/posts/**").permitAll()
                .anyRequest().authenticated()  //나머지는 로그인 필요
            )
            .exceptionHandling(e -> e                       // 로그인 안 했으면 401
                .authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED)))
            .addFilterBefore(new TokenAuthenticationFilter(tokenProvider, userDetailService),
                             UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    // React 개발 서버(5173)에서 오는 요청 허용
    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowedOrigins(List.of("http://localhost:5173"));
        config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        config.setAllowedHeaders(List.of("*"));          // Authorization 헤더 포함

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/api/**", config);
        return source;
    }

    // 비밀번호 암호화 도구(UserService에서 주입받아 사용)
    @Bean
    public PasswordEncoder passwordEncoder(){
        return new BCryptPasswordEncoder();
    }
}

10-2. api/api.ts — 토큰 인터셉터 · 401 처리 추가 (완성)

💡 src/api/api.ts — 완성
import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:8080/api',
});

// ① 요청 인터셉터 — 저장된 토큰을 Authorization 헤더에 붙인다
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// ② 응답 인터셉터 — 토큰이 만료 · 위조되어 401이면 로그아웃 처리
api.interceptors.response.use(
  (response) => response,
  (error) => {
    const isAuthApi = error.config?.url?.startsWith('/auth');   // 로그인 실패 401은 제외
    if (axios.isAxiosError(error) && error.response?.status === 401 && !isAuthApi) {
      localStorage.removeItem('accessToken');
      localStorage.removeItem('username');
      alert('로그인이 필요합니다.');
      window.location.href = '/login';
    }
    return Promise.reject(error);
  },
);

// 서버가 보낸 오류 문구 꺼내기 — { "message": "..." }
export function getErrorMessage(err: unknown): string {
  if (axios.isAxiosError(err)) {
    return err.response?.data?.message ?? err.message;
  }
  return '알 수 없는 오류가 발생했습니다.';
}

export default api;

📖 인터셉터(interceptor)란?

요청이 나가기 직전, 응답이 화면 코드에 도착하기 직전에 끼어들어 공통 작업을 하는 함수다. 화면마다 토큰을 붙이거나 401을 처리하는 코드를 쓰지 않고 한곳에서 끝낸다.

화면
createPost(form)→요청 인터셉터
Bearer 토큰 추가→서버→응답 인터셉터
401 → 로그인 화면→화면
코드의미
baseURL이후 api.get('/posts')처럼 뒷부분만 쓴다 → http://localhost:8080/api/posts
localStorage.getItem('accessToken')브라우저 저장소에서 토큰 꺼내기 (10-4 AuthProvider가 로그인할 때 저장)
`Bearer ${token}`JWT를 보낼 때 쓰는 정해진 형식 — Bearer 뒤에 공백 한 칸
!isAuthApi로그인 API의 401(비밀번호 틀림)은 화면에서 직접 문구를 보여 주므로 제외
window.location.href = '/login'페이지를 새로 불러오며 이동 → 로그인 상태가 처음부터 다시 읽힌다
Promise.reject(error)오류를 화면 코드의 catch로 넘긴다
err: unknowncatch로 받은 값은 무엇인지 모르므로 unknown → axios.isAxiosError()로 확인 후 사용
⚠️ 토큰 저장 위치 localStorage는 같은 사이트의 JavaScript라면 누구나 읽을 수 있다. 게시판에 다른 사람이 넣은 스크립트가 실행되는 XSS 취약점이 있으면 토큰을 빼앗길 수 있다. React는 {post.content}처럼 출력하면 HTML을 자동으로 이스케이프하므로 기본적으로 안전하지만, dangerouslySetInnerHTML은 쓰지 않는다. 실무에서는 httpOnly 쿠키 + 리프레시 토큰 방식도 함께 검토한다.

📖 왜 Context API인가 — 로그인 상태 vs 게시글 데이터

  • 로그인 상태는 여러 화면이 함께 쓴다 — Header(아이디 · 로그아웃) · PrivateRoute(접근 막기) · PostDetail(본인 글) · AdminRoute(관리자). props로 넘기면 App → 중간 컴포넌트 → 사용처로 줄줄이 전달해야 한다(prop drilling). Context는 useAuth() 한 줄.
  • 자주 바뀌지 않는다 — 로그인 · 로그아웃 때만 바뀌므로, “값이 바뀌면 쓰는 화면이 모두 다시 그려진다”는 Context의 약점이 거의 문제 되지 않는다.
  • 게시글 목록 · 상세는 Context에 넣지 않는다 — 화면마다 서버에서 받아 따로 쓰는 데이터라 각 화면의 useEffect로 불러온다. Context에 넣으면 목록이 바뀔 때 Header까지 다시 그려지고, 언제 다시 불러올지 직접 관리해야 한다.
  • React 기본 기능이라 라이브러리 설치가 필요 없다.
방법언제이 교안에서
Context API로그인 · 테마 · 언어처럼 앱 전체가 쓰고 가끔 바뀌는 값⭕ 로그인 상태
props 전달부모 → 자식 한두 단계⭕ AiAssistant의 title · onSelect (AI 탭)
Zustand · Redux Toolkit전역 상태가 많고 자주 바뀌는 큰 앱소개만
TanStack Query (React Query)서버 데이터의 캐시 · 재요청 · 로딩 관리소개만 — 게시글 불러오기를 대신할 수 있다
💡 React 19 새 문법 React 19에서는 <AuthContext.Provider value={…}> 대신 <AuthContext value={…}>, useContext(AuthContext) 대신 use(AuthContext)로도 쓸 수 있다. 자료가 많은 .Provider · useContext를 기본으로 쓰고, 새 문법은 알아만 둔다.

10-3. AuthContext.ts — 통로와 useAuth()

💡 src/context/AuthContext.ts
import { createContext, useContext } from 'react';
import type { AuthForm } from '../types/auth';

export interface AuthContextType {
  username: string | null;                    // 로그인 아이디 (로그인 전 null)
  isLoggedIn: boolean;
  login: (form: AuthForm) => Promise<void>;
  logout: () => void;
}

export const AuthContext = createContext<AuthContextType | null>(null);

// 화면에서 로그인 상태를 꺼내 쓰는 Hook
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth는 AuthProvider 안에서만 사용할 수 있습니다.');
  }
  return context;
}

10-4. AuthProvider.tsx — 로그인 · 로그아웃

💡 src/context/AuthProvider.tsx
import { useState } from 'react';
import type { ReactNode } from 'react';
import { AuthContext } from './AuthContext';
import { login as loginApi } from '../api/auth';
import type { AuthForm } from '../types/auth';

export default function AuthProvider({ children }: { children: ReactNode }) {
  // 새로고침해도 로그인이 유지되도록 localStorage에서 읽어 시작
  const [username, setUsername] = useState<string | null>(
    () => localStorage.getItem('username'),
  );

  const login = async (form: AuthForm) => {
    const data = await loginApi(form);                  // POST /api/auth/login
    localStorage.setItem('accessToken', data.accessToken);
    localStorage.setItem('username', data.username);
    setUsername(data.username);
  };

  const logout = () => {
    localStorage.removeItem('accessToken');
    localStorage.removeItem('username');
    setUsername(null);
  };

  return (
    <AuthContext.Provider value={{ username, isLoggedIn: username !== null, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}
코드의미
useState(() => localStorage.getItem(…))처음 한 번만 저장소를 읽어 초기값으로 (함수로 넘기면 매번 읽지 않는다)
login as loginApiAPI 함수 이름 login이 Provider의 login과 겹쳐서 다른 이름으로 가져온다
localStorage.setItem(…)토큰 · 아이디 저장 → 10-2 요청 인터셉터가 읽는다
logout저장소를 비우기만 하면 끝 — 서버에 알릴 필요가 없다 (STATELESS)
📌 파일을 둘로 나눈 이유 Context 파일(AuthContext.ts)과 컴포넌트 파일(AuthProvider.tsx)을 나눈 이유: 한 파일에서 컴포넌트와 Hook을 함께 내보내면 Vite의 빠른 새로고침(Fast Refresh)이 동작하지 않고 ESLint 경고(react-refresh/only-export-components)가 난다.

import { useState } from 'react';
import type { ChangeEvent, FormEvent } from 'react';

import { useEffect, useState } from 'react';
import type { ChangeEvent, FormEvent } from 'react';
import { useNavigate, useParams } from 'react-router-dom';
import { createPost, getPost, updatePost } from '../api/posts';
import { getErrorMessage } from '../api/api';
import type { PostForm } from '../types/post';

export default function PostWrite() {
  const { id } = useParams();                 // /posts/3/edit → "3", /posts/new → undefined
  const isEdit = id !== undefined;            // id가 있으면 수정
  const navigate = useNavigate();
  const [form, setForm] = useState<PostForm>({ title: '', content: '' });
  const [saving, setSaving] = useState(false);

  // 수정이면 기존 글을 불러와 폼에 채운다
  useEffect(() => {
    if (!isEdit) return;
    getPost(Number(id))
      .then(post => setForm({ title: post.title, content: post.content }));
  }, [id, isEdit]);

  const handleChange = (e: ChangeEvent<HTMLInputElement | HTMLTextAreaElement>) => {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
  };

  const handleSubmit = async (e: FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    if (!form.title.trim()) {
      alert('제목을 입력하세요.');
      return;
    }
    setSaving(true);                          // 저장 중 버튼 막기 (두 번 누르기 방지)
    try {
      if (isEdit) {
        await updatePost(Number(id), form);   // PUT /api/posts/{id}
        alert('수정되었습니다.');
        navigate(`/posts/${id}`, { replace: true });
      } else {
        const saved = await createPost(form); // POST /api/posts
        alert('등록되었습니다.');
        navigate(`/posts/${saved.id}`, { replace: true });
      }
    } catch (err) {
      alert(getErrorMessage(err));            // 403 · 400 문구
      setSaving(false);
    }
  };

  return (
    <div className="mx-auto" style={{ width: '60%' }}>
      <h2 className="mb-4">{isEdit ? '글 수정' : '글쓰기'}</h2>
      <form onSubmit={handleSubmit}>
        <div className="mb-3">
          <label htmlFor="title" className="form-label">제목</label>
          <input id="title" name="title" className="form-control"
                 value={form.title} onChange={handleChange} />
        </div>
        <div className="mb-3">
          <label htmlFor="content" className="form-label">글내용</label>
          <textarea id="content" name="content" className="form-control" rows={10}
                    value={form.content} onChange={handleChange} />
        </div>
        <button type="submit" className="btn btn-primary me-1" disabled={saving}>
          {isEdit ? '수정' : '등록'}
        </button>
        <button type="button" className="btn btn-secondary" onClick={() => navigate(-1)}>취소</button>
      </form>
    </div>
  );
}

import { useState } from 'react';
import type { ReactNode } from 'react';
import { AuthContext } from './AuthContext';
import { login as loginApi } from '../api/auth';
import type { AuthForm } from '../types/auth';

export default function AuthProvider({ children }: { children: ReactNode }) {
  const [username, setUsername] = useState<string | null>(
    () => localStorage.getItem('username'),
  );
  const [role, setRole] = useState<string | null>(      // 추가
    () => localStorage.getItem('role'),
  );

  const login = async (form: AuthForm) => {
    const data = await loginApi(form);
    localStorage.setItem('accessToken', data.accessToken);
    localStorage.setItem('username', data.username);
    localStorage.setItem('role', data.role);             // 추가
    setUsername(data.username);
    setRole(data.role);
  };

  const logout = () => {
    localStorage.removeItem('accessToken');
    localStorage.removeItem('username');
    localStorage.removeItem('role');                     // 추가
    setUsername(null);
    setRole(null);
  };

  return (
    <AuthContext.Provider value={{
      username, role,
      isLoggedIn: username !== null,
      isAdmin: role === 'ADMIN',
      login, logout,

import { useState } from 'react';
import { getSuggestions } from '../api/ai';
import { getErrorMessage } from '../api/api';

interface Props {
  title: string;                        // 부모(PostWrite)의 제목
  content: string;                      // 부모의 글내용
  onSelect: (text: string) => void;     // 제안을 클릭하면 부모에게 알림
}

export default function AiAssistant({ title, content, onSelect }: Props) {
  const [question, setQuestion] = useState('');
  const [suggestions, setSuggestions] = useState<string[]>([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState('');

  const handleAsk = async () => {
    if (!question.trim()) {
      alert('AI에게 물어볼 내용을 입력하세요.');
      return;
    }
    setLoading(true);                   // 응답 올 때까지 버튼 막기
    setError('');
    setSuggestions([]);
    try {
      setSuggestions(await getSuggestions({ title, content, question }));
    } catch (err) {
      setError('AI 응답 실패 : ' + getErrorMessage(err));
    } finally {
      setLoading(false);
    }
  };

  return (
    <div className="card mb-3">
      <div className="card-header">🤖 AI 글쓰기 도우미</div>
      <div className="card-body">
        <div className="input-group mb-2">
          <input className="form-control" placeholder="예: 도입부를 더 흥미롭게 하려면?"
                 value={question} onChange={e => setQuestion(e.target.value)} />
          <button type="button" className="btn btn-outline-primary"
                  onClick={handleAsk} disabled={loading}>
            {loading ? '생각 중…' : 'AI 제안'}
          </button>
        </div>

        {loading && <p className="text-muted mb-2">AI가 생각하는 중…</p>}
        {error && <p className="text-danger mb-2">{error}</p>}

        <ul className="list-group">
          {suggestions.map((text, i) => (
            <li key={i} className="list-group-item list-group-item-action"
                style={{ cursor: 'pointer' }} onClick={() => onSelect(text)}>
              {text}
            </li>
          ))}
        </ul>
        <div className="form-text">제안을 클릭하면 글내용 끝에 붙습니다.</div>
      </div>
    </div>
  );
}

2 SPA 포워딩 · SecurityConfig

🎯 학습목표
  • React 새로고침(404)을 막는 SPA 포워딩 컨트롤러를 만들 수 있다.
  • 화면 파일은 열고 /api만 검사하도록 SecurityConfig를 고칠 수 있다.

2-1. 새로고침하면 404? — SPA 포워딩

📖 왜 404가 나나

React 화면 주소(/posts/3, /admin)는 브라우저 안에서 React Router가 바꾼 것이다. 그 상태에서 새로고침하면 브라우저가 서버에 GET /posts/3을 보내는데, 서버에는 그런 파일도 컨트롤러도 없어서 404가 난다.

해결: 화면 주소로 온 요청은 모두 index.html을 돌려주고(포워딩), 나머지는 React Router가 맡게 한다.

💡 controller/SpaController.java (신규)
@Controller
public class SpaController {

    // React 화면 주소 → index.html (나머지는 React Router가 처리)
    @GetMapping({"/", "/posts", "/posts/new", "/posts/{id:\\d+}", "/posts/{id:\\d+}/edit",
                 "/login", "/signup", "/admin"})
    public String forward() {
        return "forward:/index.html";
    }
}
코드의미
forward:/index.html주소는 그대로 두고 서버 안에서 static/index.html을 보내 준다 (redirect와 다름)
{id:\d+}숫자일 때만 — /posts/3 ⭕, /posts/abc ❌
주소 목록App.tsx(A 7단원 · B 10단원)의 Route와 같게. 화면을 추가하면 여기에도 추가
📌 예전 화면 컨트롤러와 겹치지 않게 A · B 2단원에서 Thymeleaf 화면 컨트롤러(HomeController · PostViewController)를 지웠으므로 / · /posts가 겹치지 않는다. 남아 있으면 Ambiguous mapping 오류가 난다.

2-2. SecurityConfig — /api만 검사

💡 config/SecurityConfig.java — authorizeHttpRequests 수정
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**", "/error").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/posts/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/**").authenticated()     // API는 로그인 필요
                .anyRequest().permitAll()                       // 그 외(화면 · JS · CSS)는 누구나
            )
요청규칙
/ · /posts/3 · /admin · /assets/index-xxxx.jsanyRequest().permitAll() — 화면 파일은 누구나 받는다
GET /api/posts누구나
POST /api/posts · /api/ai-suggestions토큰 필요
/api/admin/**ADMIN

📖 화면을 열어도 괜찮은 이유

/admin 화면 파일은 누구나 받지만, 그 화면이 부르는 /api/admin/dashboard는 ADMIN 토큰이 있어야 한다. 데이터는 API에서 지킨다. 순서가 중요하다 — 위에서부터 처음 맞는 규칙이 적용되므로 anyRequest()는 맨 아래.

📌 CORS · 두 방식 JWT: JAR 하나로 배포하면 화면과 API가 같은 주소라 CORS 설정은 운영에서 쓰이지 않는다. 개발(5173 → 8080)에는 필요하므로 지우지 않는다. 세션: 원래 CORS 설정이 없다 — csrf.spa() · formLogin 끄기 · logout() 등 A 5단원 설정에 위 authorizeHttpRequests만 바꾼다.

💡 vite.config.ts — 빌드 결과를 바로 static으로 (선택)
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  build: {
    outDir: '../boardweb/src/main/resources/static',   // boardweb-client 옆의 서버 폴더

⚠️ 고친 뒤에는 다시 빌드 React 코드를 고쳤으면 다시 빌드 → static 교체 → 서버 다시 실행(또는 JAR 다시 빌드)해야 바뀐다. 5173 개발 서버에서만 확인하고 빌드를 빠뜨리는 일이 가장 흔하다.
