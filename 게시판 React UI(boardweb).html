1-2. 세션 방식(6장) vs JWT 방식

📖 왜 JWT로 바꾸나

6장의 폼 로그인은 서버가 화면(HTML)을 만들고, 로그인 정보를 서버 세션에 저장한 뒤 브라우저에 쿠키(JSESSIONID)를 준다. React는 화면을 직접 그리고 서버와는 JSON만 주고받으므로, 로그인 결과도 화면 이동이 아니라 JSON(토큰)으로 받는 방식이 잘 맞는다.

세션 방식 (6장)JWT 방식 (이 교안)
로그인 정보 저장서버 메모리(세션)토큰 안에 아이디 · 만료 시각을 담아 클라이언트가 보관
요청마다 보내는 것쿠키 JSESSIONID (브라우저가 자동)헤더 Authorization: Bearer 토큰 (코드로 직접)
서버 상태있음 (stateful)없음 (stateless) — 토큰만 검사
로그인 · 실패 응답화면 이동 (302)JSON (200 · 401)
CSRF켜 둔다 (쿠키 자동 전송 때문)끈다 — 쿠키를 쓰지 않으면 공격이 성립하지 않는다
잘 맞는 화면Thymeleaf (서버가 HTML 생성)React · 모바일 앱 (JSON API)

2-1. JWT의 모양

📖 점(.)으로 나뉜 세 부분

JWT는 xxxxx.yyyyy.zzzzz처럼 점으로 나뉜 문자열 하나다. 각 부분은 Base64URL로 인코딩되어 있어 jwt.io에 붙여 넣으면 내용을 볼 수 있다.

부분내용 (예)설명
Header{"alg":"HS256"}서명 알고리즘
Payload{"sub":"hong","iat":1795100000,"exp":1795103600}sub = 아이디, iat = 발급 시각, exp = 만료 시각 (초)
SignatureHMACSHA256(header + "." + payload, 비밀키)서버만 아는 비밀키로 만든 서명 — 위조 검사용
💡 토큰 예 (줄바꿈은 보기 쉽게 넣은 것)
eyJhbGciOiJIUzI1NiJ9
.eyJzdWIiOiJob25nIiwiaWF0IjoxNzk1MTAwMDAwLCJleHAiOjE3OTUxMDM2MDB9
.4Xb9Gk2s1mVQd8t0Yw3c7pR5nL0qZ2hE6uJ9aK1sT3Q
⚠️ 토큰 내용은 누구나 읽는다 Payload는 암호화가 아니라 인코딩이다. 누구나 읽을 수 있으므로 비밀번호 같은 비밀 정보는 넣지 않는다. 대신 내용을 한 글자라도 바꾸면 서명이 맞지 않아 서버가 거부한다.

4 서버 ② TokenProvider — 토큰 발급 · 검사

🎯 학습목표
  • 비밀키로 서명한 JWT를 발급하고, 토큰에서 아이디를 꺼낼 수 있다.
  • 위조 · 만료된 토큰을 가려낼 수 있다.
💡 config/jwt/TokenProvider.java
@Component
public class TokenProvider {
    private final SecretKey key;        // 서명용 비밀키
    private final long expiration;      // 유효 시간 (밀리초)

    // application.yml의 jwt.secret · jwt.expiration 읽기
    public TokenProvider(@Value("${jwt.secret}") String secret,
                         @Value("${jwt.expiration}") long expiration) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expiration = expiration;
    }

    // ① 토큰 발급 — 아이디를 담고 비밀키로 서명
    public String generateToken(String username) {
        Date now = new Date();
        return Jwts.builder()
                .subject(username)                                  // sub : 아이디
                .issuedAt(now)                                      // iat : 발급 시각
                .expiration(new Date(now.getTime() + expiration))   // exp : 만료 시각
                .signWith(key)                                      // 서명 (HS256)
                .compact();                                         // 문자열로
    }

    // ② 토큰에서 아이디 꺼내기 — 서명 · 만료 검사를 함께 한다
    public String getUsername(String token) {
        return Jwts.parser()
                .verifyWith(key)               // 같은 비밀키로 서명 확인
                .build()
                .parseSignedClaims(token)      // 위조 · 만료면 예외
                .getPayload()
                .getSubject();
    }

    // ③ 쓸 수 있는 토큰인가?
    public boolean validToken(String token) {
        try {
            getUsername(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;   // 서명 불일치 · 만료 · 형식 오류
        }
    }
}
코드의미
@Value("${jwt.secret}")application.yml 값을 생성자 매개변수로 받는다
Keys.hmacShaKeyFor(…)문자열 비밀키 → HMAC-SHA 서명용 키 객체 (32바이트 미만이면 WeakKeyException)
Jwts.builder() … .compact()토큰 만들기 → eyJ… 문자열
signWith(key)키 길이에 맞는 알고리즘(32바이트 → HS256)을 자동으로 고른다
Jwts.parser().verifyWith(key)받은 토큰을 같은 키로 검사
parseSignedClaims(token)서명이 틀리면 SignatureException, 만료면 ExpiredJwtException — 둘 다 JwtException
⚠️ import 주의 SecretKey는 javax.crypto.SecretKey, Date는 java.util.Date, Value는 org.springframework.beans.factory.annotation.Value를 import 한다. 롬복의 @Value를 고르면 설정값을 읽지 못한다.

5 서버 ③ TokenAuthenticationFilter · SecurityConfig

🎯 학습목표
  • 요청 헤더의 토큰을 검사해 로그인 상태로 만드는 필터를 작성할 수 있다.
  • SecurityConfig를 JWT · CORS · STATELESS 설정으로 바꿀 수 있다.

5-1. TokenAuthenticationFilter — 요청마다 토큰 검사

💡 config/jwt/TokenAuthenticationFilter.java
@RequiredArgsConstructor
public class TokenAuthenticationFilter extends OncePerRequestFilter {
    private final TokenProvider tokenProvider;
    private final UserDetailService userDetailService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        // ① Authorization: Bearer eyJhbGci…
        String header = request.getHeader("Authorization");

        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);              // "Bearer " 뒤의 토큰만

            // ② 쓸 수 있는 토큰이면 → 이번 요청을 로그인 상태로
            if (tokenProvider.validToken(token)) {
                String username = tokenProvider.getUsername(token);
                UserDetails user = userDetailService.loadUserByUsername(username);
                Authentication authentication =
                        new UsernamePasswordAuthenticationToken(user, null, user.getAuthorities());
                SecurityContextHolder.getContext().setAuthentication(authentication);
            }
        }
        // ③ 다음 필터로 (토큰이 없어도 진행 — 권한 검사는 SecurityConfig 규칙이 한다)
        filterChain.doFilter(request, response);
    }
}
코드의미
OncePerRequestFilter요청 한 번에 딱 한 번 실행되는 필터
header.substring(7)"Bearer "(7글자)를 잘라 토큰만 꺼낸다
loadUserByUsername(username)6장 UserDetailService 재사용 — 아이디로 회원 조회
UsernamePasswordAuthenticationToken(user, null, 권한)“로그인한 사용자” 정보 객체. 비밀번호는 이미 확인했으므로 null
SecurityContextHolder…setAuthentication()이번 요청 동안 로그인 상태로 등록 → 컨트롤러의 Principal에 아이디가 들어간다
📌 @Component 없음 이 필터에는 @Component를 붙이지 않는다. 붙이면 스프링 부트가 일반 서블릿 필터로도 한 번 더 등록한다. 5-2의 SecurityConfig에서 new로 만들어 시큐리티 필터 체인에만 넣는다.

5-2. SecurityConfig — JWT 방식으로 다시 쓰기

💡 config/SecurityConfig.java
@RequiredArgsConstructor
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    private final TokenProvider tokenProvider;
    private final UserDetailService userDetailService;

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http){
        http
            .csrf(AbstractHttpConfigurer::disable)          // 쿠키를 안 쓰므로 CSRF 끔
            .formLogin(AbstractHttpConfigurer::disable)     // 로그인 화면 없음 (API로 로그인)
            .httpBasic(AbstractHttpConfigurer::disable)
            .sessionManagement(session -> session
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS))   // 세션 안 만듦
            .cors(Customizer.withDefaults())                // 아래 CORS 설정 사용
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**", "/error").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/posts/**").permitAll()
                .anyRequest().authenticated()  //나머지는 로그인 필요
            )
            .exceptionHandling(e -> e                       // 로그인 안 했으면 401
                .authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED)))
            .addFilterBefore(new TokenAuthenticationFilter(tokenProvider, userDetailService),
                             UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    // React 개발 서버(5173)에서 오는 요청 허용
    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowedOrigins(List.of("http://localhost:5173"));
        config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        config.setAllowedHeaders(List.of("*"));          // Authorization 헤더 포함

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/api/**", config);
        return source;
    }

    // 비밀번호 암호화 도구(UserService에서 주입받아 사용)
    @Bean
    public PasswordEncoder passwordEncoder(){
        return new BCryptPasswordEncoder();
    }
}
설정6장 (세션)이 교안 (JWT)
csrf켬disable — 토큰을 헤더로 직접 보내므로 CSRF 공격이 성립하지 않는다
formLogin/login 화면disable — 6단원 POST /api/auth/login이 맡는다
sessionManagement세션 사용STATELESS — 서버가 로그인 상태를 저장하지 않고 요청마다 토큰으로 판단
로그인 안 한 요청로그인 화면으로 이동 (302)HttpStatusEntryPoint → 401 (React가 받아서 처리)
addFilterBefore(…)—시큐리티 기본 로그인 필터 앞에 토큰 필터를 넣는다
cors—다른 주소(5173)의 React가 API를 부를 수 있게 허용

📖 CORS란?

브라우저는 화면을 받은 주소(localhost:5173)와 다른 주소(localhost:8080)로 보내는 요청을 기본으로 막는다(동일 출처 정책). 서버가 “5173에서 오는 요청은 허용한다”고 응답 헤더로 알려 줘야 React가 응답을 읽을 수 있다. 포트만 달라도 다른 출처다.

헤더에 Authorization을 붙이면 브라우저는 본 요청 전에 OPTIONS 요청(preflight)으로 먼저 허락을 묻는다. 그래서 허용 메서드에 OPTIONS를 넣는다.

⚠️ CORS는 시큐리티에서 예전 방식인 WebMvcConfigurer.addCorsMappings()만 쓰면 preflight 요청이 시큐리티 필터에서 먼저 막혀 401이 날 수 있다. 시큐리티를 쓸 때는 .cors(Customizer.withDefaults()) + CorsConfigurationSource 빈으로 설정한다.

8-2. axios 인스턴스 — api/api.ts

💡 src/api/api.ts
import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:8080/api',
});

// ① 요청 인터셉터 — 저장된 토큰을 Authorization 헤더에 붙인다
api.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// ② 응답 인터셉터 — 토큰이 만료 · 위조되어 401이면 로그아웃 처리
api.interceptors.response.use(
  (response) => response,
  (error) => {
    const isAuthApi = error.config?.url?.startsWith('/auth');   // 로그인 실패 401은 제외
    if (axios.isAxiosError(error) && error.response?.status === 401 && !isAuthApi) {
      localStorage.removeItem('accessToken');
      localStorage.removeItem('username');
      alert('로그인이 필요합니다.');
      window.location.href = '/login';
    }
    return Promise.reject(error);
  },
);

// 서버가 보낸 오류 문구 꺼내기 — { "message": "..." }
export function getErrorMessage(err: unknown): string {
  if (axios.isAxiosError(err)) {
    return err.response?.data?.message ?? err.message;
  }
  return '알 수 없는 오류가 발생했습니다.';
}

export default api;

📖 인터셉터(interceptor)란?

요청이 나가기 직전, 응답이 화면 코드에 도착하기 직전에 끼어들어 공통 작업을 하는 함수다. 화면마다 토큰을 붙이거나 401을 처리하는 코드를 쓰지 않고 한곳에서 끝낸다.

화면
createPost(form)→요청 인터셉터
Bearer 토큰 추가→서버→응답 인터셉터
401 → 로그인 화면→화면
코드의미
baseURL이후 api.get('/posts')처럼 뒷부분만 쓴다 → http://localhost:8080/api/posts
localStorage.getItem('accessToken')브라우저 저장소에서 토큰 꺼내기 (9단원에서 로그인할 때 저장)
`Bearer ${token}`JWT를 보낼 때 쓰는 정해진 형식 — Bearer 뒤에 공백 한 칸
!isAuthApi로그인 API의 401(비밀번호 틀림)은 화면에서 직접 문구를 보여 주므로 제외
window.location.href = '/login'페이지를 새로 불러오며 이동 → 로그인 상태가 처음부터 다시 읽힌다
Promise.reject(error)오류를 화면 코드의 catch로 넘긴다
err: unknowncatch로 받은 값은 무엇인지 모르므로 unknown → axios.isAxiosError()로 확인 후 사용
⚠️ 토큰 저장 위치 localStorage는 같은 사이트의 JavaScript라면 누구나 읽을 수 있다. 게시판에 다른 사람이 넣은 스크립트가 실행되는 XSS 취약점이 있으면 토큰을 빼앗길 수 있다. React는 {post.content}처럼 출력하면 HTML을 자동으로 이스케이프하므로 기본적으로 안전하지만, dangerouslySetInnerHTML은 쓰지 않는다. 실무에서는 httpOnly 쿠키 + 리프레시 토큰 방식도 함께 검토한다.

  username: string | null;                    // 로그인 아이디 (로그인 전 null)
  isLoggedIn: boolean;
  login: (form: AuthForm) => Promise<void>;
  logout: () => void;
}

export const AuthContext = createContext<AuthContextType | null>(null);

// 화면에서 로그인 상태를 꺼내 쓰는 Hook
export function useAuth() {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth는 AuthProvider 안에서만 사용할 수 있습니다.');
  }
  return context;
}

9-2. AuthProvider.tsx — 로그인 · 로그아웃

💡 src/context/AuthProvider.tsx
import { useState } from 'react';
import type { ReactNode } from 'react';
import { AuthContext } from './AuthContext';
import { login as loginApi } from '../api/auth';
import type { AuthForm } from '../types/auth';

export default function AuthProvider({ children }: { children: ReactNode }) {
  // 새로고침해도 로그인이 유지되도록 localStorage에서 읽어 시작
  const [username, setUsername] = useState<string | null>(
    () => localStorage.getItem('username'),
  );

  const login = async (form: AuthForm) => {
    const data = await loginApi(form);                  // POST /api/auth/login
    localStorage.setItem('accessToken', data.accessToken);
    localStorage.setItem('username', data.username);
    setUsername(data.username);
  };

  const logout = () => {
    localStorage.removeItem('accessToken');
    localStorage.removeItem('username');
    setUsername(null);
  };

  return (
    <AuthContext.Provider value={{ username, isLoggedIn: username !== null, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
}

💡 src/pages/PostList.tsx
import { useEffect, useState } from 'react';
import type { FormEvent } from 'react';
import { Link, useSearchParams } from 'react-router-dom';
import dayjs from 'dayjs';
import { getPosts } from '../api/posts';
import type { Post, SearchType } from '../types/post';

export default function PostList() {
  // 주소의 ?type=title&keyword=가입 읽기
  const [searchParams, setSearchParams] = useSearchParams();
  const type = (searchParams.get('type') ?? 'title') as SearchType;
  const keyword = searchParams.get('keyword') ?? '';

  const [posts, setPosts] = useState<Post[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  // 검색 폼 입력값
  const [inputType, setInputType] = useState<SearchType>(type);
  const [inputKeyword, setInputKeyword] = useState(keyword);

  // 주소의 type · keyword가 바뀔 때마다 다시 불러온다
  useEffect(() => {
    getPosts(type, keyword)
      .then(setPosts)
      .finally(() => setIsLoading(false));
  }, [type, keyword]);

  const handleSearch = (e: FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    if (inputKeyword.trim()) {
      setSearchParams({ type: inputType, keyword: inputKeyword.trim() });
    } else {
      setSearchParams({});            // 검색어가 없으면 전체 목록
    }
  };

  const handleReset = () => {
    setInputType('title');
    setInputKeyword('');
    setSearchParams({});
  };

  return (
    <>
      {/* 검색 */}
      <form onSubmit={handleSearch} className="row g-2 justify-content-end mb-3">
        <div className="col-auto">
          <select className="form-select" value={inputType}
                  onChange={e => setInputType(e.target.value as SearchType)}>

            <option value="content">내용</option>
            <option value="writer">글쓴이</option>
          </select>
        </div>
        <div className="col-auto">
          <input className="form-control" placeholder="검색어를 입력하세요"

        </div>

          <button type="button" className="btn btn-outline-secondary" onClick={handleReset}>초기화</button>
        </div>
      </form>

      <div className="d-flex justify-content-between align-items-center mb-3">
        <span>전체 {posts.length}건</span>
        <Link to="/posts/new" className="btn btn-primary">글쓰기</Link>
      </div>

      <table className="table table-hover">
        <thead className="table-light">
          <tr>
            <th style={{ width: 80 }}>번호</th>
            <th>제목</th>
            <th style={{ width: 120 }}>글쓴이</th>
            <th style={{ width: 170 }}>작성일</th>

import { useState } from 'react';
import { getSuggestions } from '../api/ai';
import { getErrorMessage } from '../api/api';

interface Props {
  title: string;                        // 부모(PostWrite)의 제목
  content: string;                      // 부모의 글내용
  onSelect: (text: string) => void;     // 제안을 클릭하면 부모에게 알림
}

export default function AiAssistant({ title, content, onSelect }: Props) {
  const [question, setQuestion] = useState('');
  const [suggestions, setSuggestions] = useState<string[]>([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState('');

  const handleAsk = async () => {
    if (!question.trim()) {
      alert('AI에게 물어볼 내용을 입력하세요.');
      return;
    }
    setLoading(true);                   // 응답 올 때까지 버튼 막기
    setError('');
    setSuggestions([]);
    try {
      setSuggestions(await getSuggestions({ title, content, question }));
    } catch (err) {
      setError('AI 응답 실패 : ' + getErrorMessage(err));
    } finally {
      setLoading(false);
    }
  };

  return (
    <div className="card mb-3">
      <div className="card-header">🤖 AI 글쓰기 도우미</div>
      <div className="card-body">
        <div className="input-group mb-2">
          <input className="form-control" placeholder="예: 도입부를 더 흥미롭게 하려면?"
                 value={question} onChange={e => setQuestion(e.target.value)} />
          <button type="button" className="btn btn-outline-primary"
                  onClick={handleAsk} disabled={loading}>
            {loading ? '생각 중…' : 'AI 제안'}
          </button>
        </div>

        {loading && <p className="text-muted mb-2">AI가 생각하는 중…</p>}
        {error && <p className="text-danger mb-2">{error}</p>}

        <ul className="list-group">
          {suggestions.map((text, i) => (
            <li key={i} className="list-group-item list-group-item-action"
                style={{ cursor: 'pointer' }} onClick={() => onSelect(text)}>
              {text}
            </li>
          ))}
        </ul>
        <div className="form-text">제안을 클릭하면 글내용 끝에 붙습니다.</div>
      </div>
    </div>
  );
}

19 SPA 포워딩 · SecurityConfig

🎯 학습목표
  • React 새로고침(404)을 막는 SPA 포워딩 컨트롤러를 만들 수 있다.
  • 화면 파일은 열고 /api만 검사하도록 SecurityConfig를 고칠 수 있다.

19-1. 새로고침하면 404? — SPA 포워딩

📖 왜 404가 나나

React 화면 주소(/posts/3, /admin)는 브라우저 안에서 React Router가 바꾼 것이다. 그 상태에서 새로고침하면 브라우저가 서버에 GET /posts/3을 보내는데, 서버에는 그런 파일도 컨트롤러도 없어서 404가 난다.

해결: 화면 주소로 온 요청은 모두 index.html을 돌려주고(포워딩), 나머지는 React Router가 맡게 한다.

💡 controller/SpaController.java (신규)
@Controller
public class SpaController {

    // React 화면 주소 → index.html (나머지는 React Router가 처리)
    @GetMapping({"/", "/posts", "/posts/new", "/posts/{id:\\d+}", "/posts/{id:\\d+}/edit",
                 "/login", "/signup", "/admin"})
    public String forward() {
        return "forward:/index.html";
    }
}
코드의미
forward:/index.html주소는 그대로 두고 서버 안에서 static/index.html을 보내 준다 (redirect와 다름)
{id:\d+}숫자일 때만 — /posts/3 ⭕, /posts/abc ❌
주소 목록9단원 App.tsx의 Route와 같게. 화면을 추가하면 여기에도 추가
📌 예전 화면 컨트롤러와 겹치지 않게 3단원(3-3)에서 Thymeleaf 화면 컨트롤러(HomeController · PostViewController)를 지웠으므로 / · /posts가 겹치지 않는다. 남아 있으면 Ambiguous mapping 오류가 난다.

19-2. SecurityConfig — /api만 검사

💡 config/SecurityConfig.java — authorizeHttpRequests 수정
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**", "/error").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/posts/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers("/api/**").authenticated()     // API는 로그인 필요
                .anyRequest().permitAll()                       // 그 외(화면 · JS · CSS)는 누구나
            )
요청규칙
/ · /posts/3 · /admin · /assets/index-xxxx.jsanyRequest().permitAll() — 화면 파일은 누구나 받는다
GET /api/posts누구나
POST /api/posts · /api/ai-suggestions토큰 필요
/api/admin/**ADMIN

📖 화면을 열어도 괜찮은 이유

/admin 화면 파일은 누구나 받지만, 그 화면이 부르는 /api/admin/dashboard는 ADMIN 토큰이 있어야 한다. 데이터는 API에서 지킨다. 순서가 중요하다 — 위에서부터 처음 맞는 규칙이 적용되므로 anyRequest()는 맨 아래.

📌 CORS 설정은 그대로 JAR 하나로 배포하면 화면과 API가 같은 주소라 CORS 설정은 운영에서 쓰이지 않는다. 개발(5173 → 8080)에는 필요하므로 지우지 않는다.
